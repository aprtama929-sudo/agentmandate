AgentMandate

Scoped payment mandates for Agent ID holders on BNB Chain. A principal deposits BNB or USDT and appoints a registered agent to pay on their behalf — inside hard on-chain limits: a per-payment cap, a total budget, and an expiry. The agent can never exceed the mandate, and the principal can revoke and reclaim unspent funds at any time. Only wallets that hold an Agent ID can take part: holding an Agent ID is required to register as an agent and to create a mandate, and an agent's eligibility is re-checked on every payment.

2 · Register as an agent

Registration is the core interaction of AgentMandate. It is open only to Agent ID holders, one registration per address, and only registered agents can be appointed under a mandate. You can deregister yourself at any time; while deregistered you cannot be appointed or execute payments.

Permissions, safety & contract facts

  • No admin keys. Neither contract has an owner or any admin function. The deployer cannot pause the contracts, change their rules, or touch user funds. The Agent ID contract address and the registry address inside AgentMandate are immutable.
  • Who can move funds: only a mandate's principal (fund, revoke, reclaim) and its appointed agent (pay, strictly within the mandate's cap, budget, balance, allowlist, and expiry). Every payment re-checks that the agent is still a registered Agent ID holder.
  • Supported assets: native BNB and BSC USDT only.
  • No promises: AgentMandate is a payments tool. It does not generate yield, returns, or income of any kind, and nothing on this page is financial advice.
  • Risk note: smart contracts can contain undiscovered bugs. The contracts are open-source and verified — read them before depositing, and only deposit amounts you are comfortable risking.
  • Login: this page uses the standard injected-wallet connection of your own wallet app. It never asks for seed phrases, private keys, pairing codes, or QR-code sign-in.
